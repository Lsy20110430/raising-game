# 养成小游戏 · Tamagotchi

一个跑在自己机器上的文字养成 / 恋爱模拟小游戏。**零第三方依赖**，一个 `python3` 就能起：终端里玩，或者开个网页在手机浏览器里玩。

角色由 AI 扮演，但**所有数值都在本地结算**——好感、心情、体力、金币、经验、冷却全由本地规则算，AI 只负责台词，以及闲聊时 ±5 以内的微调。想刷也刷不动，想跑也不用连网。

```text
第 3 天 21:14   晚上
柒柒：这么晚才想起我？行吧，陪你聊两句，我稿子还没画完呢。
（+2 好感，+1 心情）
```

## 特性

- **网页版 + 终端版双入口**，共用同一套逻辑和同一个存档
- **游戏内时钟**：不操作时现实 1 秒 = 游戏 1 分钟，动作再额外推进；打工有营业时段（深夜配送 21:00-05:00 这种），深夜她也会说话带困意
- **六段关系阶段**：陌生人 → 打过照面 → 朋友 → 好朋友 → 有点心动 → 恋人，语气和态度随阶段变化
- **长期记忆**：她说过的、你送过的、你们一起去过的，会持久化写进记忆表，之后的对话里她能想起来
- **礼物 / 打工 / 娱乐 / 休息**四条玩法线，全部带等级、时段、冷却与数值门槛
- **单人 & 双人娱乐**：双人项目（看电影、密室、海边日落、夜市、livehouse、短途旅行）要好感 100 起步，每次结束都会写进她的记忆
- **三位可选角色**，各有性格、喜好与不喜欢的礼物类别
- **零依赖、无框架、无构建**，纯标准库，SQLite 单文件存档

## 快速开始

需要 Python 3.8+（开发环境 3.12，也在 Termux 的 3.14 上跑过）。

```sh
# 配置模型 Key
echo 'DEEPSEEK_API_KEY=你的key' > .env

sh run.sh          # 终端版
sh run.sh web      # 网页版，默认 http://127.0.0.1:8765/
sh run.sh web 8899 # 指定端口
```

Windows / 桌面也可以直接 `python server.py` 或 `python tui.py`。

### 手机上跑（Termux）

`/sdcard` 没有执行位，只能用 `sh` 调起来：

```sh
pkg install python
cd 目录
sh run.sh web
```

`run.sh` 会顺带 `termux-wake-lock`，免得熄屏把服务冻住。

### 配置

| 项 | 说明 |
| --- | --- |
| `DEEPSEEK_API_KEY` | 必填，`tamagotchi/.env` 或环境变量；只走服务端，绝不下发到前端 |
| `HOST` | 网页版监听地址，`run.sh web` 默认 `127.0.0.1`，直接跑 `server.py` 默认 `0.0.0.0` |
| `PORT` | 默认 `8765`，被占用会自动往后顺延 |
| `TUI_WIDTH` | 终端版在拿不到窗口宽度时用的兜底列宽 |

## 玩法

### 数值

| 数值 | 上限 | 初始 | 增减方式 |
| --- | --- | --- | --- |
| 好感度 | 1000 | 10 | 聊天（-5~+5）、礼物、双人娱乐 |
| 心情 | 100 | 60 | 聊天、礼物、娱乐、休息、打工；低于 30 打工收益打折 |
| 体力 | 100 | 100 | 每 10 游戏分钟 +1，打工 / 娱乐消耗，休息 +45 |
| 金币 | — | 120 | 打工赚，礼物与娱乐花 |
| 经验 | — | 0 | 每 80 点升一级，解锁更贵的工作与玩法 |

心情每 240 游戏分钟自然 -1，下限 15。

### 关系阶段

| 好感度 | 阶段 |
| --- | --- |
| 0 | 陌生人 |
| 50 | 打过照面 |
| 150 | 朋友 |
| 350 | 好朋友 |
| 600 | 有点心动 |
| 850 | 恋人 |

阶段决定了她的态度，也决定她能说出什么样的话。

### 四条玩法线

- **聊天**：直接打字。走 5 游戏分钟，她返回台词 + 好感/心情微调，若你透露了值得记住的信息（名字、喜好、约定、心事），她会自己记一条长期记忆。
- **礼物**（14 件）：对口的标签收益 ×2，不喜欢的标签 ×-0.25，普通 ×1；同一件礼物重复送会递减（第 n 次系数 `1-0.2(n-1)`，下限 0.45）。送出价值 30+ 好感的礼物会被她记住。
- **打工**（9 份）：街头发传单、咖啡店帮工、家教、深夜配送、便利店夜班、宠物店、图书馆、街头卖唱、搬家苦力。各有等级要求、营业时段、体力消耗与冷却；心情 ≥70 收益 ×1.2，心情 ≤30 ×0.8。卖唱收成随机性最大。
- **娱乐**（12 项）：6 个单人回心情项目（打街机、夜跑、猫咖、通宵排位、图书馆看书、泡温泉），6 个双人约会项目（好感 100 解锁，结束时一定写进记忆）。
- **休息**：睡 4 小时，+45 体力，+3 心情，冷却 6 小时。

### 网页版

信息模块固定、只有聊天区可滚。底部动作栏五颗按钮：🎁 礼物 / 💼 打工 / 🎡 娱乐 / 💤 休息 / 📔 回忆，点开底部抽屉选具体项目，冷却是实时倒计时。HTML 改动不需要重启服务（静态文件按请求读盘）。

```text
直接输入内容      和她聊天

/gift <编号>      送礼物（/gift 3）

```

## 项目结构

```text
tamagotchi/
├── server.py      HTTP 服务：静态页面 + 游戏 API（http.server）
├── tui.py         终端界面入口，复用 game / db / llm
├── game.py        核心规则：数值、时钟、阶段、礼物/打工/娱乐、AI 编排
├── llm.py         DeepSeek 调用封装（urllib，含重试）
├── db.py          SQLite 存档层
├── run.sh         启动器（TUI / web，Termux UTF-8 兜底）
├── static/        网页版前端（index.html / style.css / app.js，原生 JS）
├── .env           API Key
└── save.db        SQLite 存档
```

### 存档

单存档槽（`save.id = 1`），表结构：

| 表 | 内容 |
| --- | --- |
| `save` | 角色、人设、好感/心情/体力/金币/经验、游戏时钟 |
| `messages` | 对话历史 |
| `memories` | 长期记忆（`talk` / `gift` / `date` / `event` / `setting`） |
| `events` | 事件流（送礼、打工、约会、升级、阶段变化） |
| `cooldowns` | 各项目冷却（键：`job:<id>` / `act:<id>` / `rest`），单位是游戏分钟 |
| `gift_counts` | 每件礼物送过几次，用于收益递减 |

想重开就删掉 `save.db`，或在界面里点重新开始 / 用 `/new`。

### API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 完整状态：数值、时钟、礼物/工作/娱乐清单（含冷却与门槛）、历史、记忆、事件 |
| POST | `/api/chat` | `{ "text": "..." }` |
| POST | `/api/gift` | `{ "item_id": "daisy" }` |
| POST | `/api/work` | `{ "job_id": "cafe" }` |
| POST | `/api/activity` | `{ "activity_id": "movie" }` |
| POST | `/api/rest` | 无参数 |
| POST | `/api/reset` | `{ "persona": "qiqi" }`，重开存档 |

## 设计要点

**数值本地结算，AI 只演角色。** 好感、心情、体力的加减全在 `game.py` 里按表算，模型只能通过 `affinity_delta` / `mood_delta` 在 ±5 内影响闲聊结果。这样数值可预期、不会因为模型抽风而崩盘，也省 token。

**历史以文本塞进 system prompt。** 请求只发 system + 单条 user，因为 DeepSeek 网关在「多轮 messages + `response_format=json_object`」组合下会稳定返回空白内容。对话历史用 `_history_text()` 拼成文本块附在 system prompt 里。

**两种输出模式。** 闲聊要 JSON（台词 + 数值增减 + 记忆）；送礼、打工、休息、约会这类场景只要一句台词，用 `json_output=False` 的系统提示直接拿纯文本，避免模型对着 JSON 模式说废话。

**失败了也有台阶。** `llm.chat()` 内置重试并逐次降温（1.0 → 0.75 → 0.5），场景台词调用失败时随机挑一句兜底台词，不至于把网络抖动甩到玩家脸上。

## 常见问题

**Termux 里一启动就 `UnicodeEncodeError: 'ascii' codec can't encode ...`**
Termux 默认不设 `LANG`，Python 把 stdout 当 ascii。`run.sh` 已加 `PYTHONUTF8=1` + `PYTHONIOENCODING=utf-8`，`tui.py` / `server.py` 启动时也各自 `sys.stdout.reconfigure(encoding="utf-8")` 兜底，单独跑文件同样不崩。

**`OSError: [Errno 98] Address already in use`**
手机上的容器和 Termux 共用同一个网络命名空间，同一端口只能一方持有。`server.py` 遇到占用会自动往后试 12 个端口并打印真实地址，也可以直接 `sh run.sh web 8899` 指定。

**终端里 emoji 显示成方块**
Termux 字体通常没有 emoji 字形，终端版渲染前会把 emoji 摘掉；中文列宽用 `unicodedata.east_asian_width` 计算，纯 ASCII 终端下排版也不会错位。
